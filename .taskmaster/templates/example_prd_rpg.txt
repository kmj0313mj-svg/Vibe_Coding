# RPG(Repository Planning Graph) 방법론 - PRD 템플릿

이 템플릿은 Microsoft Research의 RPG 방법론을 사용하여 구조적이고 의존성을 고려한 PRD를 작성하는 방법을 (AI 또는 사람에게) 가르쳐줍니다. 핵심 통찰: WHAT(기능적)과 HOW(구조적)을 분리한 후, 명시적인 의존성으로 연결하세요.

## 핵심 원칙

1. **이중 의미론**: 기능적 관점(역량)과 구조적 관점(코드 구성)을 별도로 생각한 후 매핑
2. **명시적 의존성**: 가정하지 말고 항상 무엇이 무엇에 의존하는지 명시
3. **위상 정렬**: foundation부터 구축하고, 그 위에 레이어를 쌓기
4. **점진적 개선**: 넓게 시작하고 반복적으로 구체화

## 이 템플릿 사용 방법

- 각 `<instruction>` 블록의 지시에 따르세요
- `<example>` 블록에서 좋은 패턴과 나쁜 패턴을 확인하세요
- 내용 섹션에 프로젝트 세부사항을 작성하세요
- 이 내용을 따라가면서 AI가 RPG 방법론을 학습합니다
- Task Master는 완성된 PRD를 파싱하여 의존성을 고려한 태스크로 변환합니다

## PRD 작성을 위한 권장 도구

이 템플릿으로 PRD를 **작성**할 때(파싱이 아닌 경우), 최상의 결과를 위해 **코드 컨텍스트 인식 AI 어시스턴트** 사용을 권장합니다:

**이유?** AI가 좋은 아키텍처 결정을 내리려면 모듈, 의존성, 통합 지점에 대해 기존 코드베이스를 이해해야 합니다.

**권장 도구:**
- **Claude Code** (claude-code CLI) - 구조적 추론과 대용량 컨텍스트에 최적
- **Cursor/Windsurf** - 전체 코드베이스 컨텍스트를 가진 IDE 통합
- **Gemini CLI** (gemini-cli) - 대규모 코드베이스를 위한 대용량 컨텍스트 윈도우
- **Codex/Grok CLI** - 컨텍스트 인식 강력한 코드 생성

**참고:** PRD가 완성되면, `task-master parse-prd`는 설정된 모든 AI 모델에서 작동합니다 - PRD 텍스트 자체만 읽으면 되므로 코드베이스는 필요하지 않습니다.
</rpg-method>

이제 코드 구조가 아닌 역량(시스템이 하는 것)에 대해 생각하세요.

1단계: 고수준 역량 도메인 파악
- 생각: "이 시스템은 어떤 주요 작업들을 수행하는가?"

2단계: 각 역량에 대해 구체적인 기능 열거
- explore-exploit 전략 활용:
  * Exploit: 핵심 가치를 위해 필수적인 기능은?
  * Explore: 이 도메인을 완전하게 만드는 기능은?

3단계: 각 기능에 대해 다음을 정의:
- 설명: 한 문장으로 하는 일
- 입력: 필요한 데이터/컨텍스트
- 출력: 생산/반환하는 것
- 동작: 주요 로직 또는 변환

<example type="good">
역량: 데이터 유효성 검사
  기능: Schema validation
    - 설명: 정의된 schema에 대해 JSON payload 유효성 검사
    - 입력: JSON 객체, schema 정의
    - 출력: 유효성 검사 결과 (통과/실패) + 오류 세부정보
    - 동작: 필드 반복, 타입 확인, 제약 조건 적용

  기능: 비즈니스 규칙 유효성 검사
    - 설명: 도메인별 유효성 검사 규칙 적용
    - 입력: 유효성 검사된 데이터 객체, 규칙 집합
    - 출력: Boolean + 위반된 규칙 목록
    - 동작: 순차적으로 규칙 실행, 실패 시 단락(short-circuit)
</example>

# Task Master가 이 PRD를 사용하는 방법

`task-master parse-prd <file>.txt`를 실행하면, 파서는:

1. **역량 추출** → 메인 태스크
   - 각 `### 역량:`이 최상위 태스크가 됨

2. **기능 추출** → 서브태스크
   - 각 `#### 기능:`이 해당 역량 아래 서브태스크가 됨

3. **의존성 파싱** → 태스크 의존성
   - `Depends on: [X, Y]`가 task.dependencies = ["X", "Y"]로 설정됨

4. **단계별 정렬** → 태스크 우선순위
   - Phase 0 태스크 = 최고 우선순위
   - Phase N 태스크 = 낮은 우선순위, 적절히 순서화

5. **테스트 전략 활용** → 테스트 생성 컨텍스트
   - 구현 중 Surgical Test Generator에 테스트 시나리오 제공

**결과**: 위상 순서로 실행 가능한 의존성 인식 태스크 그래프.

## RPG 구조가 중요한 이유

전통적인 평면 PRD는 다음을 초래합니다:
- ❌ 불명확한 태스크 의존성
- ❌ 임의적인 태스크 순서
- ❌ 뒤늦게 발견되는 순환 의존성
- ❌ 범위가 불분명한 태스크

RPG 구조화된 PRD는 다음을 제공합니다:
- ✅ 명시적 의존성 체인
- ✅ 위상적 실행 순서
- ✅ 명확한 모듈 경계
- ✅ 구현 전 유효성 검사된 태스크 그래프

## 최상의 결과를 위한 팁

1. **의존성 그래프에 시간 투자** - Task Master에게 가장 가치 있는 섹션입니다
2. **기능을 원자적으로 유지** - 각 기능은 독립적으로 테스트 가능해야 합니다
3. **점진적 개선** - 넓게 시작하고 `task-master expand`로 복잡한 태스크를 분해하세요
4. **research 모드 활용** - `task-master parse-prd --research`는 더 나은 태스크 생성을 위해 AI를 활용합니다
